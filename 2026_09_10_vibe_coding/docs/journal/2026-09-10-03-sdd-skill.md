## מה נעשה

נוצר סקיל ל-Claude Code ב-`skills/sdd-project/`:

- **`SKILL.md`** — frontmatter (`name`, `description`, `argument-hint`,
  `allowed-tools`) והנחיות בשני מצבים: הקמת פרויקט (איסוף פרמטרים, הרצת
  הסקריפט, מילוי הנחות ברשומת הסשן, אימות), ועבודה בפרויקט קיים (הזרימה
  issue → spec → אישור → plan → אישור → קוד, רשימת בדיקה ל-spec טוב,
  רשימת חובה לסוף סשן)
- **`scripts/scaffold.py`** — Python 3 ללא תלויות. מעתיק את `templates/`
  ליעד, מחליף `{{PLACEHOLDERS}}`, נותן לרשומות היומן והסשן הראשונות את
  תאריך ההקמה, מדלג על קבצים קיימים אלא אם `--force`, ומזהיר אם נשארו
  placeholders
- **`templates/`** — 27 קבצים: גרסה גנרית של כל השלד. הקבצים הגנריים
  (כללים, תבניות, README של ערוצים) הועתקו כמו שהם; הקבצים הספציפיים
  (AGENTS, README, team, status, issues, plan 0001, decision 0001, יומן
  וסשן ראשונים) נכתבו מחדש עם placeholders
- **`README.md`** — התקנה (symlink אישי / של פרויקט / העתקה), שימוש, פלט
  אמיתי מהרצה, טבלת placeholders, מקורות

**הרצה בארגז החול** (`scratchpad/sdd-test`): 27 קבצים נוצרו, `grep "{{"`
ריק, הרצה חוזרת דילגה על כל 27 בלי לדרוס.

נוצר symlink `.claude/skills/sdd-project` → `../../skills/sdd-project` כדי
שהסקיל יהיה פעיל בפרויקט הזה. נבדק שהוא נפתר ל-`SKILL.md`.

עודכנו: `README.md` ו-`AGENTS.md` (שורה על הסקיל), `issues/README.md`
(0004 סגור), `progress/status.md`. נוצרו `plans/0004` ו-`issues/0004`.

## למה

תומר ביקש סקיל "בסגנון של הפרוייקט" כדי להקים פרויקטים כאלה בעתיד.
הבחירה בסקריפט + תבניות, ולא בהנחיות טקסט בלבד, כי 27 קבצים שסוכן כותב
מחדש בכל פעם ייצאו שונים בכל פעם; תבניות מבטיחות שלד זהה.
