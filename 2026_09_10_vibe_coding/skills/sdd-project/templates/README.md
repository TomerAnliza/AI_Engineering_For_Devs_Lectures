## מה זה

פרויקט משותף שבו עובדים **כמה בני אדם וכמה סוכני AI** במקביל על אותו קוד.
שיטת העבודה בנויה על שני עקרונות:

1. **תיעוד כזיכרון משותף.** כל סוכן וכל אדם קוראים את התיעוד לפני שהם
   עובדים, וכותבים אליו לפני שהם מסיימים. מה שלא כתוב במסמך — לא קרה
2. **Spec Driven Development.** לפני שיוצרים מערכת, קוד או רכיב תוכנה,
   כותבים תיאור ותיעוד של הדרישות ממנו, ואדם מאשר. הקוד נכתב מול המסמך

## מבנה

```text
.
├── README.md                 # הקובץ הזה
├── AGENTS.md                 # הוראות לכל סוכן, בכל כלי
├── CLAUDE.md                 # נקודת כניסה ל-Claude Code (טוען את AGENTS.md)
├── progress/                 # ההווה: status.md — מה גמור, בעבודה, חסום, הבא
├── issues/                   # הבעיה: תקלות ומשימות פתוחות, עם אינדקס
├── specs/                    # הדרישות: מה הרכיב עושה, לפני שיש קוד
├── plans/                    # הדרך: איך נעשה, לפני שעושים
└── docs/
    ├── README.md             # מפת התיעוד
    ├── team.md               # מי עובד כאן
    ├── conventions/          # הכללים
    ├── journal/              # יומן פעולות + טבלת מעקב + ערוץ דיונים
    ├── sessions/             # תיעוד הצ׳אטים
    └── decisions/            # החלטות ארכיטקטוניות
```

הזרימה בין התיקיות:

```text
issues → specs → plans → קוד + בדיקות → docs/journal → progress
```

קוד נכנס תחת `src/` ו-`tests/`, **ורק אחרי spec ותוכנית מאושרים.** כל
תיקיית קוד מקבלת `README.md` עם: מה זה, איך מריצים, מה הרעיון.

## איך מתחילים

**אדם שמצטרף:**

1. קרא את `docs/conventions/collaboration-rules.md`
2. הוסף את עצמך ל-`docs/team.md`
3. `progress/status.md` — איפה הפרויקט עומד. `issues/README.md` — מה פתוח
4. לפני כל משימה: `docs/journal/00-tracking.md` — מה תפוס ומה פנוי

**סוכן שמצטרף:** `AGENTS.md` נטען אוטומטית. אם לא — זו הפעולה הראשונה.

**רוצים לבנות משהו חדש?** לא מתחילים מקוד. מתחילים מ-`issues/` (מה חסר),
אחר כך `specs/` (מה בדיוק נדרש), אחר כך `plans/` (איך). אדם מאשר את
ה-spec ואת התוכנית, ורק אז נכתב קוד.

**כדי לוודא שהתיעוד שלם** לפני קומיט:

```bash
ls docs/journal docs/sessions progress plans issues specs
```

מה שרואים במסך כשזה עובד: לכל תאריך עבודה יש לפחות רשומת יומן אחת
(`YYYY-MM-DD-NN-slug.md`) ורשומת סשן אחת, ותאריך העדכון בראש
`progress/status.md` הוא של אותו יום.

## Git

- ענף לכל משימה: `feat/<שם>-<slug>` או `docs/<שם>-<slug>`
- קומיטים קטנים, הודעה שמסבירה *למה*
- `main` מתעדכן ב-merge בלבד, אחרי שאדם עבר על השינוי
- סודות ב-`.env` בלבד, מסונן ב-`.gitignore`
