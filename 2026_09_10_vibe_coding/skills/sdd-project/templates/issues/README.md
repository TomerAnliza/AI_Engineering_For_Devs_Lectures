# issues — מה שבור, מה חסר, מה מחכה

כל דבר שדורש טיפול ועדיין לא טופל: תקלה, משימה, שאלה שמחכה להכרעה.
issue הוא **הבעיה**; ה-spec ב-`specs/` הוא **הדרישות**; התוכנית ב-`plans/`
היא **הדרך**; רשומת היומן היא **מה נעשה**.

## אינדקס

מתעדכן בכל פתיחה או סגירה. פתוחים למעלה.

| # | כותרת | סטטוס | על מי | נפתח |
|---|---|---|---|---|

## שם הקובץ

```text
issues/NNNN-slug.md
```

מספר רץ ארבע-ספרתי לכל הפרויקט. spec ותוכנית שפותרים issue מקבלים את
אותו מספר.

## מחזור החיים

| סטטוס | משמעות |
|---|---|
| פתוח | זוהה, אף אחד לא עובד עליו |
| בטיפול | מישהו רשום עליו כאן ובטבלת המעקב |
| ממתין להכרעה | דורש החלטה של אדם. מי ומה — כתוב בגוף |
| סגור | נפתר. רשומת היומן שסגרה אותו מקושרת |
| לא יטופל | הוחלט לא לפתור. הסיבה כתובה בגוף |

**issue לא נמחק.** סגור נשאר בתיקייה ובאינדקס.

## מי פותח

כל אחד, אדם או סוכן. סוכן שמזהה בעיה מחוץ לתחומו **פותח issue במקום לתקן**.
זה המנגנון של "מדווח, לא מבצע".
